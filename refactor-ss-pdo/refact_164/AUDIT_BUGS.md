# AUDIT BUGS — Refactor 164: QUIC Payload Projection & Realtime WebSocket Stabilization

## Daftar Temuan Masalah & Ketidaksesuaian

| ID Temuan | Lokasi Kode | Keparahan | Deskripsi Singkat | Dampak User | Mitigasi |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **BUG-164-01** | `src/services/allRouteMonitoringService.ts` | **High** | Kueri `daily_unit_summaries` menggunakan `select('*')` untuk 3 tanggal sekaligus (H, H-1, H-7), menarik >1.350 baris data JSON termasuk kolom teks catatan bus (`all_notes`, `catatan_shift1`). Paket UDP HTTP/3 (QUIC) terfragmentasi atau di-reset router/ISP lokal sehingga memicu `net::ERR_QUIC_PROTOCOL_ERROR 200 (OK)`. | Layar monitoring berisiko gagal memuat data saat jaringan ISP/WiFi mengalami fluktuasi packet loss UDP, dan konsol browser dipenuhi error merah. | Terapkan *field projection* `select('route_code, year, month, day, total_passengers, total_km, toa_shift1, manual_shift1, toa_shift2, manual_shift2')` untuk memangkas ukuran transfer >70% tanpa mengurangi data perhitungan. Tambahkan *silent retry loop* (attempt 1–2 dengan jeda 350ms). |
| **BUG-164-02** | `src/services/allRouteMonitoringService.ts` | **Medium** | Kueri `daily_fleet_shifts` dan `fetchRegionalPeriodMonitoringData` (`daily_route_reports`) tidak memiliki mekanisme *silent retry* saat terjadi lonjakan latensi sesaat. | Jika satu paket HTTP mengalami gangguan sementara, data laporan periode langsung kosong/gagal render tanpa kesempatan pemulihan otomatis. | Bungkus pemanggilan `supabase.from('daily_fleet_shifts')` dan `supabase.from('daily_route_reports')` dengan silent retry 2x attempt. |
| **BUG-164-03** | `src/components/monitoring/AllRouteMonitoringPage.tsx` | **High** | Subscription Realtime WebSocket `supabase.channel("monitoring-realtime-reports")` memiliki dependency `[loadData]`. Karena `loadData` diperbarui setiap kali tanggal, periode, atau data berubah, koneksi WebSocket diputus dan disambung ulang (*connection churning*) secara terus-menerus, memicu `WebSocket connection to 'wss://...' failed`. | Konsol browser memunculkan error merah WebSocket connection failed berulang-ulang, membebani thread browser dan memicu rekoneksi liar di latar belakang. | Gunakan `loadDataRef = useRef(loadData)` dan inisialisasi subscription hanya 1 kali saat mount (`[]`). Tambahkan handler status subscription (`CHANNEL_ERROR`, `TIMED_OUT`) untuk meredam unhandled network drop secara hening (*graceful*). |
| **BUG-164-04** | `src/services/supabase.ts` | **Low** | Inisialisasi client Supabase tidak memiliki konfigurasi timeout realtime, menggunakan batas waktu default yang terlalu ketat untuk koneksi internet dengan latensi tinggi. | Handshake WebSocket gagal lebih cepat pada jaringan seluler/tethering yang memiliki latensi tinggi. | Tambahkan opsi `realtime: { timeout: 20000, params: { eventsPerSecond: 10 } }` pada `createClient`. |
