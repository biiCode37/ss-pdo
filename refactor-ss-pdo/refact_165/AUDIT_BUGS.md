# AUDIT BUGS: Refactor 165 - Generator Laporan WA Format 3 & Rincian Unit Kesiapan Armada

## Ringkasan Eksekutif
Audit ini dilakukan menyusul laporan ketidaksesuaian data pada fitur **Generator Laporan WhatsApp Format 3 (Status Kesiapan Armada Per Shift: Shift 1 & Shift 2)**. Pengguna (Korlap/Korwil/Pengawas) mendapati bahwa rute yang berstatus **"TIDAK LENGKAP"** tidak menampilkan nomor bodi unit beserta keterangan khususnya. Akibatnya, pemangku kepentingan di lapangan bertanya-tanya mengenai penyebab berkurangnya kesiapan armada rute, unit mana yang terkendala fisik/mogok, dan unit mana yang libur (OFF) atau memiliki catatan operasional khusus.

---

## Tabel Temuan Masalah (Bug Findings)

| ID Temuan | Lokasi Kode | Keparahan | Deskripsi Masalah | Dampak Pengguna (User / Korlap / Korwil) | Mitigasi / Solusi |
|---|---|---|---|---|---|
| **BUG-165-01** | `src/utils/waReportGenerator.ts` | **HIGH** | `generateWaReportFormat3` sebelumnya hanya menampilkan daftar unit jika diklasifikasikan sebagai kendala non-OFF. Unit dengan catatan khusus saat beroperasi atau unit libur (OFF) tidak terakomodasi dengan subheader yang jelas, dan jika rincian unit kosong pada rute TIDAK LENGKAP, laporan tidak memberikan penjelasan apa pun. | Pembaca laporan WA kebingungan mengapa armada berstatus TIDAK LENGKAP tetapi tidak ada keterangan unit yang tidak beroperasi atau terkendala. | Menambahkan pemilahan 3 kategori unit: `kendalaUnits`, `offUnits`, dan `specialOperatingUnits` (unit beroperasi dengan catatan khusus). Menambahkan baris peringatan fallback `Rincian unit belum dilengkapi (-N unit)` jika rincian unit belum ada di sistem. |
| **BUG-165-02** | `src/components/monitoring/tabs/MonitoringWaReportTab.tsx` | **HIGH** | Pencarian data shift `matchingShift` menggunakan perbandingan string langsung `s.route_code === r.routeCode` tanpa normalisasi karakter titik/spasi (`JAK 01` vs `JAK.01`) dan tanpa pengecekan ID rute (`s.route_id === r.id`). | Data input cepat Korlap atau laporan A2 petugas tidak terdeteksi untuk rute dengan variasi penulisan spasi/titik, menyebabkan data jatuh ke fallback kosong. | Gunakan normalisasi kode rute `normalizeRouteCode` dan pemadanan `s.route_id === r.id || normalizeRouteCode(s.route_code) === normalizeRouteCode(r.routeCode)`. |
| **BUG-165-03** | `src/services/allRouteMonitoringService.ts` | **HIGH** | Pada fungsi `fetchRegionalMonitoringData`, field `fleetStatusShift1` dan `fleetStatusShift2` hanya mengambil `todayReport?.fleet_status_shift1`. Jika laporan hari ini berasal dari sinkronisasi sheet global (`daily_route_reports`), kolom tersebut kosong `[]`. Query `daily_fleet_shifts` di service tidak menyertakan join ke tabel `daily_fleet_non_sgo_units`. | Unit non-SGO yang sudah diinput oleh petugas A2 atau Korlap hilang dari pemantauan wilayah dan generator laporan WA ketika membuka tab monitoring. | Query `daily_fleet_non_sgo_units` berdasarkan `shiftIds` di `allRouteMonitoringService`, lalu jadikan sebagai fallback pintar saat `todayReport.fleet_status_shift1/2` kosong. |
| **BUG-165-04** | `src/components/waReport/useWaReportData.ts` | **HIGH** | Terdapat logika anomali `Math.max(r.realopsShift2 || 0, r.realopsShift1 || 0)` yang memalsukan realisasi operasi Shift 2 menjadi sama dengan Shift 1. Selain itu terdapat pengurangan ganda `Math.min(rawRealops, Math.max(0, renops - kendalaCount))` yang memotong realops secara tidak valid. | Angka realisasi operasi Shift 2 tidak mencerminkan data aktual di lapangan, dan angka armada aktif rute terpotong ganda sehingga persentase kesiapan menjadi tidak akurat. | Hapus pemalsuan `Math.max` dan pengurangan ganda. Gunakan `rawRealops` murni dari shift terkait (`r.realopsShift1` untuk S1, `r.realopsShift2` untuk S2). |
| **BUG-165-05** | `src/components/fleetStatus/QuickKorlapFleetModal.tsx` | **MEDIUM** | Parsing teks input cepat korlap `parseKorlapUnitNote` menggunakan regex sederhana yang gagal memisahkan kode operator multikata (misal "KWK 222177", "SAF 05", "TS.02") serta pencocokan substring `includes('TO')` yang salah menangkap kata "RADIA**TO**R" sebagai kode status TO. | Catatan kendala seperti "TS.02 Radiator bocor" salah terdeteksi unit "TS.02" berstatus TO padahal status kendalanya adalah MOGOK/RUSAK, atau unit multikata terpotong. | Rancang parser regex cerdas yang mengenali prefix operator Mikrotrans, gunakan boundary regex `hasWord` untuk mendeteksi kata kunci status secara ketat, dan dahulukan pengecekan kendala fisik. |
| **BUG-165-06** | `src/utils/waReportGenerator.ts`, `MonitoringWaReportTab.tsx`, `useWaReportData.ts` | **MEDIUM** | Catatan operasional rute (`operationalIssues`) yang disimpan pengawas lapangan tidak pernah diteruskan ke payload `RouteFleetReportItem` dan diabaikan oleh generator Format 3. | Catatan hambatan lalu lintas, banjir, atau rekayasa trayek tidak terbaca di laporan WA Format 3. | Tambahkan field `operationalIssues?: string` pada `RouteFleetReportItem` dan tampilkan subheader `*Catatan Operasional Rute:*` di bawah rincian unit jika ada isinya. |
| **BUG-165-07** | `src/services/regionalIngestionService.ts` | **MEDIUM** | Unit yang beroperasi namun memiliki catatan di spreadsheet (misalnya: "TUKAR SHIFT 2", "PINJAM JAK.15") sebelumnya dimasukkan ke array `nonSgoUnits` dengan `isOff: false` tanpa penanda khusus, sehingga dianggap unit kendala yang tidak beroperasi dan mengurangi realops. | Unit yang sebenarnya berjalan normal di jalanan terhitung sebagai unit mogok/kurang di dashboard dan laporan WA. | Tambahkan atribut `isOperatingWithNote?: boolean` pada `FleetUnitStatusDetail`, pisahkan unit kendala eksplisit (`isExplicitKendala`) dari unit beroperasi dengan catatan (`isOperatingWithNote`), sehingga realops tidak terpangkas keliru. |
| **BUG-165-08** | `supabase/functions/sheet-sync-webhook/index.ts` | **CRITICAL** | Webhook Google Apps Script (`CentralizedMasterRealtimeSync.js`) memicu sinkronisasi realtime saat file rute tunggal diedit, namun fungsi `sheet-sync-webhook` sebelumnya hanya menghitung angka akumulasi bus aktif (`activeBusesS1/S2`) tanpa mengekstrak dan menyimpan array rincian unit (`fleet_status_shift1` dan `fleet_status_shift2`) ke tabel `daily_route_reports`. Selain itu tidak ada guard untuk melindungi data jika Korlap sudah melakukan konfirmasi resmi di aplikasi. | Di laporan WA Format 3 muncul penanda `[Rincian unit belum dilengkapi (-N unit)]` meskipun di file spreadsheet rute tunggal sudah ada nomor bodi bus dan kolom keterangan kendala sudah terisi. Selain itu, input manual Korlap berisiko tertimpa data mentah spreadsheet jika ada edit sel belakangan. | Ekstrak nomor unit dan keterangan per shift (`nonSgoUnitsS1` & `nonSgoUnitsS2`) dari baris spreadsheet rute tunggal dengan klasifikasi kendala vs off vs beroperasi dengan catatan. Terapkan *Safe Realtime Guard* yang memeriksa `is_fleet_confirmed_s1/s2` dan `data_source === "app_input"`; jika sudah dikonfirmasi resmi oleh Korlap di aplikasi, data unit & realops manual Korlap dipertahankan. Deploy Edge Function versi 4 ke Supabase. |

Pada fungsi penarikan 18 rute (`ingestRegionalRouteSummaries`), filter Smart Skip memeriksa `status === 'submitted'` tanpa mengecek `data_source`. Sistem salah mengira data webhook tersebut sebagai input resmi final dari aplikasi, sehingga rute dilewati (di-skip) saat pengguna menekan tombol "Load All". | Saat pengguna menekan tombol "Load All" di monitoring wilayah, rute-rute yang baru diedit di spreadsheet tidak ditarik datanya karena di-skip secara diam-diam oleh logika Smart Skip. Pengguna mengira sinkronisasi macet atau gagal. | 1) Ubah status bawaan webhook mesin menjadi `'draft'` (bukan `'submitted'`), kecuali jika laporan memang sudah disubmit oleh Korlap di aplikasi. 2) Ubah filter Smart Skip tombol Load All agar hanya men-skip rute jika statusnya `verified` atau (`submitted` dan BUKAN dari `sheet_ingestion`). 3) Terapkan Safe Realtime Guard pada `extractRouteDailyMetrics` agar Load All tetap melindungi data resmi Korlap. |
